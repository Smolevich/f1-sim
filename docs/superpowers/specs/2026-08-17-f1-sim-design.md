# F1 Sim — дизайн

Дата: 2026-08-17
Статус: утверждён, готов к плану реализации

## Что строим

Браузерный симулятор Формулы-1 на three.js: реальные трассы, симуляционная физика
болида, тайм-триал с призраком, глобальный leaderboard топ-5 на трассу.

Живёт на `games.smolevich.com`, репо `Smolevich/f1-sim` — **публичный**.

Ключевое решение по глубине: это симулятор, а не аркада. Физика честная
(raycast-подвеска, слип-углы, температура шин), играбельность на клавиатуре
достигается **отключаемыми ассистами**, а не упрощением модели.

## Инфраструктура

Всё едет на **hetzner-bot**, как остальные проекты: поддомен на стороне Cloudflare,
дальше туннель на сервер. Cloudflare Pages не используем — это исключение,
оставшееся за `smolevich.com`, а не наш стандарт.

```
games.smolevich.com  → CNAME на туннель telegram-bot
                     → cloudflared ingress
                     → nginx :80        (статика игры)
                     → uvicorn :8095    (API leaderboard, путь /api/*)
```

- Туннель `telegram-bot`, UUID `d5c3afe5-554c-45ae-975c-59f0bff8f985`
  (locally-managed, конфиг в репо `hetzner`:
  `hardening/cloudflared/config.yml`)
- DNS: CNAME `games` → `<uuid>.cfargotunnel.com`, заводится с сервера
  (`cloudflared tunnel route dns`) либо API-токеном из Keychain
- **Порт 8095** — свободен: заняты 8080–8084, 8090–8092, 8094
- `game.smolevich.com` (единственное число) уже занят туннелем на nginx —
  не трогаем, наш поддомен `games`
- **Access не вешаем**: игра публичная

Статику раздаёт nginx — по правилу из `server-facts.md` прослойка нужна ровно
там, где есть файлы с диска, и это наш случай. API живёт отдельным сервисом на
своём порту, cloudflared разводит по пути:

```yaml
- hostname: games.smolevich.com
  path: ^/api/
  service: http://127.0.0.1:8095
- hostname: games.smolevich.com
  service: http://localhost:80
```

Правка ingress идёт в репо `hetzner` и деплоится оттуда, не руками на сервере.

### API leaderboard

FastAPI + uvicorn в `/opt/f1-sim/api`, systemd-юнит — как `find-job`, `finance`,
`family`. Хранилище — **SQLite** в `/opt/f1-sim/data/leaderboard.db`, прецедент
`health-dashboard`. Для топ-5 на шесть трасс этого с запасом; бэкап через
`cron.daily`, как у соседних сервисов.

```sql
CREATE TABLE laps (
  id INTEGER PRIMARY KEY,
  track TEXT NOT NULL,
  name TEXT NOT NULL,
  time_ms INTEGER NOT NULL,
  sectors TEXT NOT NULL,      -- JSON: три сплита
  assists TEXT NOT NULL,      -- JSON: какие ассисты были включены
  created_at INTEGER NOT NULL,
  ip_hash TEXT NOT NULL       -- для rate limit, не сам IP
);
```

Сырые IP не храним — только хеш с солью, для rate limit этого достаточно.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Сборка | Vite + TypeScript | как на main-site |
| Рендер | three.js | по ТЗ |
| Физика | `@dimforge/rapier3d-compat` | детерминизм, скорость — см. ниже |
| API | FastAPI + uvicorn | как find-job, finance, family |
| Хранилище | SQLite | как health-dashboard |
| Тесты | vitest (клиент), pytest (API) | чистые функции без моков |
| UI | ванильный TS | игровой цикл рулит сам, React мешает |

React сознательно не берём: цикл `requestAnimationFrame` + императивный HUD
проще и быстрее, чем реконсиляция на 60 Гц.

### Почему Rapier

Rapier — физический движок на Rust, собранный в WASM. Сборка `-compat` грузит
WASM инлайном, без отдельной возни с загрузкой `.wasm` в Vite.

Реальных вариантов под браузер три:

| | Rapier | cannon-es | ammo.js |
|---|---|---|---|
| Язык | Rust → WASM | JS | C++ (Bullet) → WASM |
| Скорость | самая высокая | ниже в разы | высокая |
| Детерминизм | да, кросс-платформенный | нет | частично |
| Raycast vehicle | есть в API | есть | есть |
| Поддержка | активная | почти заброшен | обёртка тяжёлая, API сырое |

Решающий аргумент — **детерминизм**. У нас leaderboard: одинаковый ввод обязан
давать одинаковый круг на любой машине, иначе рекорды несравнимы и призрак
расходится с записью. Rapier это даёт, cannon-es — нет.

Второй аргумент — фиксированный шаг 1/120 с: JS-движок на такой частоте съедает
бюджет кадра, WASM — нет.

## Физика

### Шаг симуляции

Фиксированный **1/120 с** с аккумулятором, рендер — сколько вытянет железо.
Без этого на 144 Гц машина едет иначе, чем на 60, и рекорды несопоставимы.
Это требование к корректности leaderboard, а не оптимизация.

### Модель

Rigid body + **raycast vehicle**: 4 луча вместо колёс-коллайдеров. Так делают
все сим-движки — стабильнее и дешевле, чем честные цилиндры в солвере.

**Шины** (`tyres.ts`) — упрощённая Pacejka Magic Formula:
- продольный и боковой слип → сила
- круг трения: разгон и поворот одновременно = срыв
- температура: холодные не держат, перегретые тоже; окно ~90–110 °C
- износ по кругам, три состава (soft / medium / hard)

**Аэродинамика** (`aero.ts`):
- прижим ~ v², баланс перед/зад из сетапа
- лобовое сопротивление
- DRS: открытое крыло на прямых — меньше прижим, выше скорость

**Подвеска** (`vehicle.ts`):
- жёсткость и демпфирование на луч
- перенос веса при торможении и в поворотах — машина приседает и кренится,
  и это меняет сцепление на осях

**Трансмиссия** (`drivetrain.ts`):
- 8 передач, кривая мощности ДВС
- ERS: буст и рекуперация, ограниченный запас на круг

### Сетап

Перед заездом: угол крыльев, передаточные числа, давление шин, тормозной баланс,
состав шин. Сетап входит в запись результата.

### Ассисты

Каждый отключается независимо. Дефолт для клавиатуры — включены первые два.

| Ассист | Что делает | Дефолт |
|---|---|---|
| Сглаживание руля | цифровой ввод → плавный угол | вкл на клаве |
| Автокоробка | переключает передачи | вкл |
| Тракшн-контроль | режет тягу при пробуксовке | выкл |
| ABS | не даёт заблокировать колёса | выкл |
| Линия торможения | подсказка на трассе | выкл |

Набор ассистов пишется вместе со временем: заезды без ассистов в leaderboard
видно отдельно.

## Трассы

Шесть: **Монца, Монако, Спа, Сильверстоун, Сузука, Интерлагос**.

### Источник геометрии

Осевые линии — из **OpenStreetMap** (лицензия ODbL, свободная). Реальная геометрия
поворотов, а не рисованная от руки.

Пайплайн `scripts/build-track.ts`, гоняется один раз при разработке:

```
OSM way → сглаженный сплайн → полотно (ширина, виражи)
        → границы трассы и зоны срезки
        → отбойники, поребрики, простая геометрия окружения
        → track/<name>.json в репо
```

В рантайме игра ходит только в свой же JSON. Никаких обращений наружу.

**Рельеф** для Спа (Eau Rouge, перепад ~40 м) и Интерлагоса — из открытых данных
высот. Без вертикали Спа теряет смысл.

### Проверка

Длина сгенерированной трассы сверяется с официальной (Монца 5.793 км,
Монако 3.337 км, Спа 7.004 км и т.д.). Расхождение больше 2 % — трасса собрана
неверно, это тест, а не глазомер.

### Реальные рекорды круга

В конфиге трассы, для призрака-эталона и как верхняя планка валидации:

| Трасса | Рекорд | Кто, год |
|---|---|---|
| Монца | 1:21.046 | Баррикелло, 2004 |
| Монако | 1:12.909 | Хэмилтон, 2021 |
| Спа | 1:46.286 | Боттас, 2018 |
| Сильверстоун | 1:27.097 | Ферстаппен, 2020 |
| Сузука | 1:30.983 | Хэмилтон, 2019 |
| Интерлагос | 1:10.540 | Ферстаппен, 2018 |

Значения перепроверяются при реализации и хранятся в конфиге с указанием источника.

## Режим заезда: тайм-триал с призраком

Имя вводится на старте, живёт в localStorage.

- Три сектора на трассу, дельта к лучшему кругу в реальном времени
- Фиолетовые секторы (личный лучший)
- Призрак: полупрозрачный болид — свой лучший круг или темп реального рекордсмена
- Запись призрака: позиция + поворот на 20 Гц, ~50 КБ на круг, localStorage

Результат заезда = время лучшего круга → отправляется в leaderboard.

## Leaderboard

FastAPI + SQLite, топ-5 **на каждую трассу**.

```
GET  /api/leaderboard?track=monza  → топ-5
POST /api/leaderboard              → отправка результата
```

### Откуда берётся планка «слишком быстро»

Сравнивать наше время с реальным рекордом трассы **некорректно**: реальный рекорд
поставлен реальным болидом, а у нас своя модель физики. Она вполне может ехать
быстрее или медленнее настоящей машины — это ничего не говорит о читерстве.

Поэтому планка берётся **из самого сима, а не из реальности**:

1. На каждой трассе при разработке прогоняется эталонный быстрый круг — идеальная
   траектория, без ассистов, полный газ где можно. Это `simRecord`: физический
   предел нашей модели на этой трассе.
2. То же самое посекторно: `simSector[1..3]`.
3. Значения кладутся в конфиг трассы рядом с геометрией.
4. Валидация: время быстрее `simRecord` с запасом 2 % → отклонить. Сектор быстрее
   `simSector[i]` с тем же запасом → отклонить.

Запас в 2 % нужен, потому что эталонный круг — не абсолютный оптимум: живой игрок
может найти траекторию лучше. Планка отсекает невозможное, а не выдающееся.

**`simRecord` пересчитывается при каждом изменении физики.** Поменяли шины или
аэродинамику — старая планка больше не соответствует модели, и её надо
перегенерировать, иначе честные заезды начнут отклоняться. Это часть работы над
физикой, а не отдельная задача.

Реальные рекорды (Баррикелло 1:21.046 и т.д.) в валидации **не участвуют вообще**.
Они нужны только для призрака-эталона и как справочная цифра на экране.

### Остальные правила

- круг без всех трёх секторов → не засчитан
- срезка (выезд за границы) или ресет на круге → не засчитан
- вместе со временем шлётся: трасса, набор ассистов, сплиты по секторам
- сумма секторов не сходится с временем круга → отклонить
- имя: длина и набор символов ограничены, обрезка по длине
- rate limit по хешу IP

Клиентскую игру полностью защитить нельзя: физика считается в браузере, и её можно
подменить. Цель — отсечь очевидное, а не построить анти-чит. Ограничение осознанное
и зафиксировано здесь, чтобы следующая сессия не пыталась «починить» его введением
тяжёлого анти-чита.

## Модель болида

**База — процедурная геометрия по реальным пропорциям F1** (регламент):
длина 5.6 м, ширина 2.0 м, колёсная база 3.6 м, колёса 18", halo, антикрыло,
барджборды.

**GLTF-загрузчик — готовый путь рядом.** Если в ходе работы находится модель с
честной свободной лицензией (CC0 или CC-BY с атрибуцией), она подключается без
изменений в физике. Не находится — игра всё равно выходит.

Причина такой развязки: CC0-моделей болидов F1 мало, большинство на Sketchfab —
CC-BY или non-commercial. Вешать релиз на поиск ассета нельзя.

**Ливреи и команды — вымышленные.** Репо публичный, логотипы команд F1 — чужой
товарный знак. Стилистика реальная, названия свои.

## Тестирование

vitest, без моков собственного кода.

Чистые функции тестируются напрямую:
- `tyres`: холодная шина держит хуже прогретой; перегретая тоже; круг трения
  не даёт складывать полный разгон с полным поворотом
- `drivetrain`: ERS расходуется и восстанавливается, запас на круг не превышается
- `laptimer`: дельта считается верно; круг с срезкой не засчитан; сумма секторов
  сходится с временем круга
- `validation` (pytest): время быстрее `simRecord` отклоняется; сумма секторов,
  не сходящаяся с кругом, отклоняется; валидное время принимается
- `track/loader`: длина каждой собранной трассы сходится с официальной (±2 %)
- `ghost`: записанный и воспроизведённый круг совпадают по времени

Регрессионный тест на каждый пойманный баг, формулировка «баг не вернулся».

Физика проверяется ещё и **эталонными заездами**: круг на средней трассе должен
попадать в разумный коридор относительно реального рекорда. Если сим выдаёт
Монцу за 40 секунд — модель неверна, и это видно автоматически.

## Деплой

GH Actions по эталону `voice-ai/.github/workflows/deploy.yml`, строго по
`~/pet-projects/docs/hetzner-ci-deploy-standard.md`:

1. **Триггер:** `push` в `main` + `paths` + `workflow_dispatch`,
   `concurrency: deploy-f1-sim`
2. **Preflight:** vitest + pytest + `npm run build`. Сломанное до сервера не едет
3. **Tailscale:** `tailscale/github-action@v2`, tags `tag:gha-runner`
4. **Заливка:** `appleboy/scp-action@v1` в `/tmp/deploy-f1-sim-*`
5. **Установка:** `appleboy/ssh-action@v1` — перенос в `/opt/f1-sim`, установка
   `.service`, `daemon-reload`, `restart`

На сервер ходим по tailnet (`VDS_HOST`), не по публичному IP. gh-secrets:
`VDS_HOST`, `VDS_PORT`, `VDS_USER`, `VDS_SSH_KEY`, `VDS_SSH_PASSPHRASE`,
`TS_OAUTH_CLIENT_ID`, `TS_OAUTH_SECRET`.

Секрет приложения один — соль для хеша IP, читается **из Vault** в скрипте
деплоя, не из gh-secrets и не из репо.

Чего не делаем: локального билда с rsync на прод мимо CI (инцидент voice-ai
2026-07-10 — локальный билд затёр CI-билд, GA молчал двое суток) и ручной правки
`.service` или кода на сервере.

Правка ingress туннеля — в репо `hetzner`, деплоится оттуда.

### Публичный репо — что проверить до первого пуша

- ни одного токена, ID аккаунта, адреса сервера в коде и конфигах
- `.gitignore`: `node_modules/`, `.env`, `dist/`, `.wrangler/`
- ассеты только со свободной лицензией, источники записаны в `docs/assets.md`
- ливреи вымышленные, логотипов реальных команд нет

## Порядок работ

1. Каркас: репо, Vite + TS, CI по эталону voice-ai, ingress + DNS, деплой пустой
   страницы на `games.smolevich.com` — сначала работающий деплой, потом содержимое
2. Физика: чистые модули с тестами, затем связка с Rapier
3. Одна трасса (Монца) целиком: пайплайн OSM → JSON → меш
4. Тайминг, HUD, призрак
5. `simRecord` для Монцы, затем leaderboard: FastAPI + SQLite, валидация
6. Остальные пять трасс + их `simRecord`
7. Сетап, ассисты, ввод с геймпада и руля
8. Полировка: звук, камеры, эффекты

Пункт 1 намеренно первый: инфраструктура проверяется до того, как в неё поедет
игра. Пункт 5 идёт после физики и трассы, потому что планку валидации нельзя
посчитать раньше, чем появится модель, на которой её меряют.
