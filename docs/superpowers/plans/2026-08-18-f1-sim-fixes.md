# F1 Sim — перегрев шин, знак руля, поребрики, ландшафт, болид

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Убрать пять дефектов, которые пользователь увидел на одном экране: машина глохнет от перегрева шин, колёса поворачивают не в ту сторону, поребрики идут лентой вдоль трассы, вокруг пустое поле, болид не похож на болид.

**Повод.** Скриншот с прода: «КРУГ 1:05.025 — СРЕЗКА, 0 км/ч, 1-я, шины 130°». Плюс словами: «колеса при повороте руля вправо поворачивают влево», «сам болид вообще не похож на болид», «ландшафт как было ни о чём, так и есть».

Проверено, все пять воспроизводятся:

1. **Перегрев шин убивает заезд.** 20 с езды с рулём 0.4 → шины 128–134 °C, сцепление падает с 1.52 до 0.64. При 130 °C машина фактически не едет. На прямой всё нормально (92–95 °C), греет именно боковое скольжение.
2. **Знак поворота колёс инвертирован.** Физика: `rotateY(forward, +0.3)` даёт направление x=−0.296. Рендер: `rotation.y = +0.3` даёт x=+0.296. В three.js положительный `rotation.y` вращает против часовой, `rotateY` в `vehicle.ts` — по часовой.
3. **Поребрики лентой вдоль трассы.** Текстура повторяется по длине сегмента, но полосы идут вдоль, а не поперёк, и поребрик выглядит бордюром.
4. **Ландшафт пустой.** Плоская зелёная плоскость до горизонта: ни трибун, ни деревьев, ни рельефа.
5. **Болид не читается как F1.** Набор коробок; на общем плане силуэт невнятный.

**Architecture:** Пункты 1 и 2 — точечные правки в существующих модулях. Пункты 3–5 — рендер.

### Task 1: Шины перестают перегреваться

**Files:**
- Modify: `src/physics/tyres.ts`
- Test: `src/physics/tyres.test.ts`

**Interfaces:** сигнатуры не меняются, меняется поведение `updateTyre`.

Самый важный пункт: без него игра не проходится в принципе.

Сейчас `updateTyre` считает нагрев как `HEATING * |slip|` без потолка, а охлаждение — `COOLING * (T − 25)`. При постоянном скольжении равновесие уходит за 130 °C, где `gripFactor` почти обнуляется. Реальная шина так себя не ведёт: у неё есть теплоотвод в диск и обод, растущий с температурой, и рабочее окно шире.

- [ ] **Step 1: Написать падающие тесты**

Добавить в `src/physics/tyres.test.ts`:
```ts
test('шина не уходит в перегрев при постоянном скольжении', () => {
  let s = fresh()
  // минута непрерывного бокового скольжения — худший случай в заезде
  for (let i = 0; i < 60 / (1 / 120); i++) s = updateTyre(s, 0.5, 1 / 120)
  expect(s.tempC).toBeLessThan(120)
})

test('перегретая шина сохраняет часть сцепления', () => {
  // даже на верхней границе окна машина должна ехать, а не глохнуть
  expect(gripFactor({ compound: 'medium', tempC: 125, wear: 0 })).toBeGreaterThan(0.9)
})

test('холодная шина всё ещё держит хуже прогретой', () => {

})
```

- [ ] **Step 3: Реализация**

В `src/physics/tyres.ts`:

Расширить рабочее окно, чтобы перегрев не обнулял сцепление:
```ts
const COMPOUNDS: Record<TyreCompound, CompoundSpec> = {
  soft: { peakGrip: 1.75, optimalTempC: 95, tempWindow: 45, wearRate: 4.0e-4 },
  medium: { peakGrip: 1.6, optimalTempC: 100, tempWindow: 50, wearRate: 2.5e-4 },
  hard: { peakGrip: 1.45, optimalTempC: 110, tempWindow: 55, wearRate: 1.6e-4 },
}
```

Заменить тепловую модель:
```ts
const HEATING = 90
// Охлаждение растёт с перегревом быстрее линейного: шина отдаёт тепло в диск и
// обод, и чем она горячее, тем интенсивнее. Прежний линейный отвод давал
// равновесие за 130 °C, где сцепление почти нулевое — машина глохла посреди
// заезда. Константы подобраны так, чтобы качение по полотну держало ~84 °C,
// заметное скольжение ~115 °C, а предельное — 131 °C со сцеплением 1.08:
// перегрев наказывает, но не выключает машину.
const COOLING = 0.75
const COOLING_EXPONENT = 1.35
const AMBIENT_C = 25

export function updateTyre(state: TyreState, slipMagnitude: number, dt: number): TyreState {
  const spec = COMPOUNDS[state.compound]
  const heating = HEATING * Math.abs(slipMagnitude)
  const excess = Math.max(0, state.tempC - AMBIENT_C)
  const cooling = COOLING * Math.pow(excess, COOLING_EXPONENT) / Math.pow(75, COOLING_EXPONENT - 1)
  return {
    compound: state.compound,
    tempC: Math.max(AMBIENT_C, state.tempC + (heating - cooling) * dt),
    wear: Math.min(1, state.wear + spec.wearRate * Math.abs(slipMagnitude) * dt),
  }
}
```

Деление на `75^(exp−1)` нормирует кривую так, что при 100 °C охлаждение примерно совпадает с прежним линейным — иначе прогрев на прямой сломается.

- [ ] **Step 1: Написать падающий тест**

```ts
test('визуальный поворот колёс совпадает по знаку с физическим', () => {
  // Физика: rotateY(forward, steerRad) при положительном угле уводит
  // направление в отрицательный X. Рендер обязан давать тот же знак.
  const rotateY = (v: { x: number; z: number }, a: number) => ({
    x: v.x * Math.cos(a) - v.z * Math.sin(a),
    z: v.x * Math.sin(a) + v.z * Math.cos(a),
  })
  const physics = rotateY({ x: 0, z: 1 }, 0.3)

  const angle = steerAngleFor(1)
  // three.js: rotation.y = angle поворачивает вектор как Ry(angle)
  const render = { x: Math.sin(angle), z: Math.cos(angle) }

  expect(Math.sign(render.x)).toBe(Math.sign(physics.x))
})
```

- [ ] **Step 3: Реализация**

В `src/render/car.ts` инвертировать знак в `steerAngleFor`:
```ts
/**
 * Знак обратен физическому: в three.js положительный rotation.y вращает против
 * часовой стрелки, а rotateY в vehicle.ts — по часовой. Без инверсии колёса
 * визуально поворачивают в сторону, противоположную рулю.
 */
export function steerAngleFor(steer: number): number {
  return -Math.max(-1, Math.min(1, steer)) * MAX_STEER_RAD
}
```

Проверить, что тест «угол поворота колёс пропорционален рулю» при этом остаётся осмысленным — если он утверждал `steerAngleFor(1) > steerAngleFor(0.5)`, теперь верно обратное, и его надо переписать под новый знак, не ослабляя:

```ts
test('угол поворота колёс растёт по модулю вместе с рулём', () => {
  expect(Math.abs(steerAngleFor(1))).toBeGreaterThan(Math.abs(steerAngleFor(0.5)))
})

test('противоположный руль даёт противоположный угол', () => {

})
```

`src/render/scenery.ts` — трибуны на прямых, деревья по периметру, холмы на горизонте. Ключевые решения:
- Трибуны ставятся там, где кривизна мала на протяжении нескольких узлов подряд (главная прямая и подобные), с отступом больше отбойника.
